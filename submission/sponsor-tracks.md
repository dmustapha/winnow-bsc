## Altana: Best Built with Altana (50K XP, winner-take-all)

**What we use:** `@altananetwork/sdk` 0.9.0, Keystore session grant / execute / revoke, `isValidKey` reads.
**Where in the code:** `winnow-app/src/lib/altana.ts` (session lifecycle), `winnow-app/src/app/api/activate/route.ts`, `winnow-app/src/app/api/revoke/route.ts`, `winnow-app/src/app/api/sessions/route.ts`, `winnow-app/src/app/api/overcap-demo/route.ts`.
**What it does in our project:** Hiring an agent mints an Altana session with a per-day spend cap, a call allowlist, and an expiry, registered in the onchain Keystore (`0x6b8361C29d05D498b1a12B54A37310f94171E94A`). The user sees the cap and time-remaining in the UI and can revoke in one transaction. The over-cap path is proven: a spend above the cap reverts onchain with `ExceededSpendLimit` and the session stays live, which is the point of a leash.
**Wallets (Altana submission requirement):** operator `0xc211C942946011859ca634F22400d80570ED12A5`; second attestor `0x5e6cBAb6C130C21f329209697e050773f72F92c1`. Session keys and every tx hash are in `proof.md` and at https://winnow-bsc.onrender.com/proof.
**Proof of integration:**
- Grant / in-cap execute / revoke full lifecycle, all status 0x1: grant `0x49ad9032a7205e4a1b74b1a0848e0d42924ab46cf44c8eea13fad42ade7cc8b8`, in-cap capped spend `0xd4eb4e03a1a2f1a425cb76e1bc3a220711acf4d3da4df20345d25442a44484e3`, revoke `0xb54c5db4adff7291f382dcac8dda425ea05d24350c59a003d47adf2bc43f56ac`.
- Standing judging-window session #6 is LIVE (grant `0x08e0a0215801840eaf1a61bd77522014588891f41351f669584165ce8948d875`, cap 0.005 BNB), verifiable at https://winnow-bsc.onrender.com/api/sessions.
- Over-cap revert `ExceededSpendLimit`: recompute live with `RUN_LIVE=1 npx tsx tests/falsify/overcap-live.test.ts`.
**Integration depth:** Gold. Full session lifecycle onchain, in-product view and revoke, enforced over-cap revert.
> **Honest note:** Sessions are granted from one operator EIP-7702 smart wallet, with per-agent wallets as the allowlisted call targets. This is a deliberate custody-minimizing demo design (one funded key, every grant capped, expiring, and revocable onchain). Per-agent Altana wallets are the roadmap; the Keystore enforcement story is identical in both models. The x402/B402 sell-side is not shipped this window.

## TermiX: TermiX Challenge ($6K / $3K / $1K)

**What we use:** The required Agent Advantage Report, three real tasks run both ways.
**Where in the code:** `winnow-app/submission/AGENT-ADVANTAGE-REPORT.md` (report) generated by `winnow-app/scripts/agent-advantage.ts`; agent legs use `winnow-app/src/lib/agents/strategies.ts`.
**What it does in our project:** Three tasks (grid trading, health-factor assessment, yield routing) run with the marketplace agent versus manual step-by-step execution, with wall-clocked timings, per-decision cost, a scoring rubric, and every output attached verbatim. One is a trading task with a window label, calibration framing, and an explicit risk statement.
**Proof of integration:** raw run artifacts in `winnow-app/submission/advantage-runs/`; the trading task includes a labeled evaluation window and risk statement.
**Integration depth:** Gold on honesty. The candid finding: on raw recorded seconds the operator-tooled manual path wins two of three tasks; the agent's provable advantage is cost per decision (about $0.0004 to $0.0005) and unattended 24/7 cadence. The report states this plainly instead of inventing a multiplier.
> **Honest note:** The agent LLM legs ran through the local Claude CLI fallback during report generation because the API key was creditless at build time; cost is a token estimate at haiku list prices. Manual clocks are operator-tooling lower bounds, not human-at-keyboard times, and the report says so.

## PancakeSwap: PancakeSwap Challenge (1000 CAKE)

**What we use:** PancakeSwap v3 primitives, pool `slot0` ticks and the Quoter.
**Where in the code:** `winnow-app/src/lib/agents/strategies.ts` (rebalance and grid strategies), `winnow-app/src/lib/config.ts` (Quoter `0xB048Bbc1Ee6b733FFfCFb9e9CeF7375518e25997`, factory-resolved WBNB/USDT pool `0x36696169C63e42cd08ce11f5deeBbCeBae652050`).
**What it does in our project:** The Rebalancing reference agent (Winnow Ranger) reads PCS v3 pool tick versus position range and decides rebalances; the Grid Trading agent (Winnow Gridsmith) quotes both directions on PCS and places grid decisions with a risk statement. Both follow PancakeSwap's own "Building Trading Agents on V3" guide.
**Proof of integration:** these agents are two of the four live reference agents on the marketplace, graded by the same probe engine; real mainnet reads against the PCS v3 pool.
**Integration depth:** Silver. Real PCS v3 reads driving two live categories, read-heavy and capped by construction so no user funds are at risk.
> **Honest note:** Winnow does not execute swaps for users; the PCS benefit is smarter, safe automated liquidity and grid decisioning, not custody of trader funds.
